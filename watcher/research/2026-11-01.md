## What the video says (and why it matters)

The talk reduces a coding agent to three building blocks:

1. **Function calling** — a five-step loop: give tools → model requests one → run it →
   append the result to message history → model answers. [10:31]
2. **Retrieval and context** — the model must be given the right files. [02:10]
3. **Code execution** — read, edit, list, run. [12:39]

Forge already implements (1) and (3): its pipeline runs tools and verifies with real
commands. The gap the video names — **retrieval and context** — is exactly where Forge is
weak, and exactly what the Aider finding addresses.

## The proposal (Section 8, tagged: forge)

**Problem.** Forge chooses context by counting task keywords in *file paths*
(`Firstborn/src/agent/forge.ts` ~line 558). A function the task names is invisible unless
its path contains the word, and a file that *calls* the target is never discovered.

**Source.** Aider's `aider/repomap.py` — a PageRank graph over code symbols
(`watcher/knowledge/reverse/aider-repomap.md`).

**Proposed fix.** Replace the keyword-in-path sort with a symbol graph: extract
def/ref tags, build `referencer → definer` edges with Aider's weighting
(`mentioned ×10`, distinctive-name ×10, `_`-prefix ×0.1, >5-definers ×0.1, `sqrt(refs)`,
chat-file ×50), run personalized PageRank seeded by the task text, and take the top files
that fit Forge's existing 16 KB context budget.

**Confidence.** HIGH on the algorithm (read from source). MEDIUM on port cost (needs a
tree-sitter or `ts`-compiler symbol pass in TypeScript).

**Risk.** LOW. It is a swap behind Forge's current `sourceCandidates` step; a test can
assert that a called-but-not-named file appears in context.

**Evidence.** Aider: 49,871★. Algorithm read in full this session. Forge selector read at
`forge.ts` lines 520–605.
