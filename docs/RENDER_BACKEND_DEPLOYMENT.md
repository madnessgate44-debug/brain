# Brain backend deployment readiness (Render)

## Safety state

This configuration is prepared on the review branch only. It does not create a Render service, deploy code, merge the pull request, or reveal any existing GitHub secrets. Review the pull request and its CI before creating the service.

## Render configuration

The root `render.yaml` defines a Python web service in Frankfurt, starts the existing FastAPI application factory, checks `/health`, and sets `autoDeploy: false` so later Git pushes do not silently deploy. The API control key is generated by Render. Model-provider settings are marked `sync: false` and must be entered in Render's dashboard before AI chat/company workflows can work; do not copy credentials into this file or GitHub source.

The persistent disk is mounted at `/var/data`; both SQLite and the workspace/artifact directory are configured beneath it. This is necessary because mission state and artifact files currently use local SQLite/filesystem storage. Keep the service at one instance while using SQLite and a persistent disk.

## Cost and persistence

The blueprint deliberately uses a paid `0.5c-512mb` web-service plan and a 1 GB persistent disk. Render's published pricing currently lists the 0.5 CPU / 512 MB plan at **US$7/month** and persistent SSD storage at **US$0.25/GB/month**, so the baseline is approximately **US$7.25/month**, before taxes, bandwidth overages, model-provider charges, or other usage. Verify the current price in the Render dashboard before provisioning:
- https://render.com/pricing

A free web service is not a safe substitute for this configuration: its local filesystem is ephemeral, it spins down after 15 minutes idle, and local SQLite/artifact data can be lost on restart, spin-down, or redeploy. A free Render Postgres database is not a durable alternative; Render says it expires after 30 days. See https://render.com/docs/free.

The disk preserves local files through ordinary restarts/redeploys, but it is not a database backup or disaster-recovery plan. SQLite on a single persistent disk is a single-instance arrangement; it does not support horizontally scaled API replicas. Configure and test backups before storing important missions/artifacts.

## Secrets required before use

- `BRAIN_CONTROL_API_KEY`: generated by Render; keep it private and use it only in the Brain interface's session-only key field.
- `BRAIN_AI_BASE_URL`, `BRAIN_AI_MODEL`, `BRAIN_AI_API_KEY`: enter the approved model-provider endpoint, model, and secret in Render's environment settings. Existing GitHub Actions secrets are not automatically copied to Render.
- `BRAIN_CORS_ORIGINS`: currently limited to `https://madnessgate44-debug.github.io`. Change only if the actual frontend origin differs.

## Release checklist

1. Review this configuration and the application/security changes in the pull request.
2. Confirm the plan and disk cost in Render before provisioning.
3. Merge only after the pull request is reviewed and its required checks pass.
4. Create/sync the Render Blueprint from the reviewed `main` branch.
5. Enter model-provider secrets in Render; never commit them.
6. Retrieve the generated control key securely and enter it in the frontend session.
7. Verify HTTPS, `/health`, rejection of unauthenticated control requests, authenticated connection, create/read mission, event retrieval, artifact retrieval, restart persistence, and bounded failure handling.
8. Do not call Brain production-ready until those checks pass and backups are tested.
